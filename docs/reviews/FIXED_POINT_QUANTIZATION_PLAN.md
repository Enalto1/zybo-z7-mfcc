# 고정소수점 양자화 계약 (Q0)

작성: 2026-10-04 Asia/Seoul. 작성 범위: 고정소수점 수치 설계·RTL 검증.
정정: 2026-10-04, 사용자 인계 지시에 따라 고정소수점 수치 실험을 이어받았다.
범위: [FIXED_POINT_DEVELOPMENT.md](../FIXED_POINT_DEVELOPMENT.md) 4장의 **Q0**.
16비트 선행 실험은 [FIXED_POINT_PILOT.md](FIXED_POINT_PILOT.md), 확장 후보 비교는
[FIXED_POINT_PRECISION_REVIEW.md](FIXED_POINT_PRECISION_REVIEW.md)에 있다.

후속 정밀도 실험의 우선 후보는 내부·출력20/F19, 입력16/F15, BFP 목표0.975다.
Fw16 조건에서 이 후보의 Power/Mel 누산 폭은 unsigned40/60이며, 아래 기존16비트의
32/52와 구분한다. 최종 허용치·전체 정수 전처리·log/DCT 형식은 여전히 미확정이다.

이 문서는 **단계별 수치 계약과 미확정 항목**을 기록한다. 전체 고정소수점 MFCC의 완성이
아니다. 이번에 정수로 구현한 단계는 FFT 입력 양자화·FFT·Power·Mel뿐이고,
pre-emphasis/framing/window와 log/DCT는 float64로 남아 있다.

`MFCC_SPEC.md`는 수정하지 않았다. 규격 변경 제안은
[FFT_SPEC_HANDOFF.md](FFT_SPEC_HANDOFF.md)와 이 문서 6장에 둔다.

## 1. 단계별 수치 계약

공통 수학 정의는 `MFCC_SPEC.md` 2~3장이다. 아래 표의 "값 해석"은 모두
`정수 * 2^-F`이며, 프레임별 BFP 지수 `s`는 F에 섞지 않고 따로 전달한다.

### 1.1 입력과 전처리 (이번 작업에서 정수화하지 않음)

| 단계 | signed | W | F | scale/exponent | 이론 범위 | 개발 입력 관측 범위 | 곱 폭 | 누산 guard | 양자화 위치/모드 | overflow 정책 | 상태 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| PCM | yes | 16 | 15 | `s/32768` | `[-1, 1)` | 개발 음성 peak 정수 미기록 | — | — | 없음(정수 보존) | 해당 없음 | **확인** (`MFCC_SPEC.md:입력`) |
| pre-emphasis 계수 0.95 | yes | 미확정 | 미확정 | — | — | — | 미확정 | — | 미확정 | 미확정 | **미확정** |
| pre-emphasis 출력 `y` | yes | 미확정 | 미확정 | — | `\|y\| <= 1.95` (수학적 상한) | `\|y\|` 최대 미기록 | 미확정 | 미확정 | 미확정 | 미확정 | **미확정** |
| 윈도 계수(Hamming) | unsigned | 미확정 | 미확정 | — | `[0.08, 1]` | 동일 | 미확정 | — | 미확정 | 미확정 | **미확정** |
| windowed `u` | yes | float64 | — | — | `\|u\| <= 1.95` | **peak 6.393e-4 … 5.647e-1** (개발 534프레임) | — | — | 없음(이번에는 float64) | 해당 없음 | **확인**(관측), 정수화는 **미확정** |

관측 범위는 개발 음성 1개의 534프레임에서 나온 값이다. 모든 입력의 안전성을 뜻하지 않는다.
적대 입력(full-scale 교대 등)에서는 `|u|`가 1.95에 근접할 수 있다.

### 1.2 FFT 입력 양자화 (이번 작업에서 구현)

| 항목 | 값 | 상태 |
|---|---|---|
| signed / W / F | signed / **16** / **15** | **확인** — 재사용 FFT 코어의 포트 계약 |
| 변환식 | `in[n] = quantize(u[n] * 2^(s-1))` | **후보** — `s`는 후보마다 다름 |
| 반올림 | 최근접, **ties-to-even**, 값의 정확한 2진 표현에서 판정 | **후보** |
| overflow 정책 | **saturate** 후 `[-32767, +32767]` clamp | **후보** |
| clamp 근거 | FFT 재사용 검토에서 시험한 두 적대 신호군의 실수 입력 overflow가 모두 `-32768` 코드에서 관측됐고, 대칭 clamp가 그 관측 사례를 제거했다. **일반 증명이 아니다** | **확인(관측 범위 한정)** |
| 고정 배율 후보 | `s = 0` → `α = 1/2` → `\|z\| <= 0.975` | **후보** |
| BFP 후보 | `s = max{s : peak * 2^(s-1) * 2^15 <= T}` , `T` = 목표 정수 peak. **반올림 전 peak 비교** | **후보** — 보존된 pilot 실행과 같은 보수적 규칙 |
| BFP `T` | 16384(= 0.5 FS) / 31949(약 0.975 FS) 두 값을 실험 | **후보** — 확정값 아님 |
| `s` 허용 범위 | `[-2, 24]`, 무음(`peak == 0`)은 `s = 0` | **후보** |
| 큰 진폭 fallback | `s = shift_min`에서도 목표를 못 맞추면 지수 제한을 기록하고, 실제 표현 범위 초과 시 saturate/clamp를 별도 집계 | **후보** |

기존 문서의 `round(peak * scale) <= T` 표기는 실제 코드와 달라 철회한다.
`pipeline.py:choose_bfp_shift`는 float64 입력의 정확한 2진 값을 `Fraction`으로 비교한다.
반올림 후 비교는 별도 `SHIFT_RULE_ROUNDED` 후보이며 보존 실행을 그 규칙으로 다시 해석하지 않는다.
예를 들어 `peak=65537/131072`, `T=16384`이면 `s=1`의 반올림 전 값은
16384.25여서 기본 규칙은 `s=0`을 고른다. 반올림 후 비교는 `s=1`을 고를 수 있다.

clipping 집계는 **서로 다른 frame-sample 수**와 **단계별 이벤트 수**를 구분한다.
같은 음수 샘플이 width saturation과 대칭 clamp를 모두 거치면 샘플은 1개, 이벤트는 2회다.
겹치는 프레임에 같은 PCM 위치가 다시 들어오면 프레임마다 별도 양자화하므로 각각 센다.
`pilot_03_fixed_accounting`의 D 후보는 923 frame-samples / 1,385 events이며,
기존의 "1,385 샘플" 표기는 잘못된 집계 설명이었다.

양자화 손실(개발 534프레임, `\|u - in/2^15/2^(s-1)\|`):

| 후보 | max | RMSE |
|---|---|---|
| 고정 `α=1/2` | 3.052e-5 | 1.762e-5 |
| BFP(T=0.5 FS) | 3.052e-5 | **4.172e-6** |
| Q15 후 shift(보조) | 4.577e-5 | 8.990e-6 |

### 1.4 Power (이번 작업에서 구현)

| 항목 | 값 | 상태 |
|---|---|---|
| `psum[k] = out_re^2 + out_im^2` | **unsigned 32비트**, 반올림 없음(정확) | **확인** |
| 최대값 | `2 * 32768^2 = 2^31` (입력 `-32768` 쌍) | **확인** — `test_power_mel.py` |
| 실수 환산 | `P[k] = psum[k] * 2^-(19 + 2s)` (N=512, S=9) | **확인** — 직접 유도 후 `check_scale_derivation()`으로 대조 |
| 일반식 | `P = psum * 2^(2S + 2 - 2s - 2F_out - log2 N)`; 이 절은 `F_out=15` | **확인** |
| 양자화 | 이 단계에서는 **없음** | **확인** |

여기서 S는 **물리적인 FFT 축소량**(N512에서 9)이다. 내부 F19→출력 F15 재표현의
정수 코드 우측 이동 4비트는 S에 추가하지 않는다. 출력 F를 사용하는 위 식에 그 4비트를
다시 더하면 배율이 중복 반영된다. 확장 후보의 `W/F_out`과 폭 산식은 정밀도 보고서에서 구분한다.

### 1.5 Mel 누산 (이번 작업에서 구현)

| 항목 | 값 | 상태 |
|---|---|---|
| 가중치 `w_int[m][k] = round(B * 2^Fw)` | `Fw` = **16 후보**. 12/14/16/18/20을 측정 | **후보** |
| 가중치 signedness/W | **unsigned**, `Fw + 1` 비트 (peak 1.0 = `2^Fw`를 정확히 표현해야 함) | **확인** |
| 반올림 | ties-to-even, 정확한 2진 값에서 판정 | **후보** |
| 곱 폭 | `32 + (Fw+1)` = 49비트(Fw=16), 반올림 없음 | **확인** |
| 누산 `T_m = Σ_k psum[k] * w_int[m][k]` | **unsigned**, 반올림 없음 | **확인** |
| 누산 폭(이 계수표 기준 tight) | **52비트** (최대 band 가중치 합 23.5·2^16, worst band 25) | **후보 설정에서 유도 확인** |
| 누산 폭(전 bin 가중치 1 가정 loose) | 56비트 | **확인** |
| 실수 환산 | `E_m = T_m * 2^-(19 + 2s + Fw)` | **확인** |
| overflow 정책 | 폭이 증명 가능하므로 **ERROR**(발생 시 보고) | **후보** |

32비트 psum·49비트 곱·52비트 누산은 **FFT 출력 signed16/F15 및 Fw=16 후보**의
범위 계산이다. 전체 설계의 최종 폭을 확정한 것이 아니며, 출력 폭이나 Mel 계수가 바뀌면
곱과 누산 상한을 다시 계산한다. Python 무제한 정수 계산과 파일 저장 형식의 안전성도 별도 확인한다.

Mel **계수 양자화만의** 오차(개발 power 128프레임, 양쪽 동일 float64 power 사용):

| Fw | 가중치 폭 | max\|계수오차\| | max\|ΔE\| | max 상대 ΔE | max\|Δln E\| (nats) | tight 누산 비트 |
|---:|---:|---:|---:|---:|---:|---:|
| 12 | 13 | 1.172e-4 | 1.209e-4 | 2.435e-4 | 2.435e-4 | 48 |
| 14 | 15 | 2.930e-5 | 6.434e-6 | 1.200e-4 | 1.200e-4 | 50 |
| **16** | **17** | **7.324e-6** | **6.852e-6** | **2.294e-5** | **2.294e-5** | **52** |
| 18 | 19 | 1.831e-6 | 1.889e-6 | 3.805e-6 | 3.805e-6 | 54 |
| 20 | 21 | 4.578e-7 | 1.005e-7 | 1.144e-6 | 1.144e-6 | 56 |

이 오차는 **FFT 입력/단계 양자화와 분리해서 측정한 값**이다. Fw=16에서 로그 영역 기여는
2.3e-5 nats로, 2장의 전체 오차(0.4~1.7 nats 수준)보다 4~5 decade 작다.
즉 **현재 지배적인 오차원은 Mel 계수가 아니다.** 그렇다고 Fw=16을 확정값으로 쓰지 않는다 —
전체 경로가 개선되면 다시 평가해야 한다.

### 1.6 log (이번 작업에서 정수화하지 않음)

| 항목 | 값 | 상태 |
|---|---|---|
| 정의 | `L_m = ln(max(E_m, 1e-12))`, `1e-12`는 **정규화 E 단위** | **확인** (`MFCC_SPEC.md:92`) |
| floor 비교 위치 | **BFP 지수까지 반영한 `E_m = T_m * 2^-(19+2s+Fw)`** 에서 비교 | **확인** |
| 중요한 성질 | `s`가 커지면 **양수 정수 `T_m`도 floor 아래일 수 있다.** `T_m == 0`만 보는 shortcut은 BFP 경로에서 틀리다 | **확인** — `test_power_mel.py`에서 `s=10`(지수 `-55`)일 때 경계 `T = 36029` 확인 |
| 고정 `s=0`의 경우 | 지수 `-35`, 양자 `2.910e-11 > 1e-12`이므로 `T >= 1`이면 floor가 걸리지 않는다. **이는 `s=0`에 한정된 성질** | **확인** |
| 정수 구현(정규화 + LUT/근사) | 폭·구간·오차 모두 **미확정** | **미확정** |

현재 로그는 float64다. 로그 영역에서 관측 오차가 커지는 것은 작은 에너지의 상대 오차와
floor 전환이 비선형적으로 확대된 결과이며, 아직 구현하지 않은 정수 로그의 오차가 아니다.
향후 정수 log는 추가 양자화 오차를 검증해야 하고, 앞 단계에서 0으로 사라진 에너지를 복원하지 못한다.

## 2. 양자화 연산 도구

`software/fixed_model/qnum.py`. 설계 원칙:

- 모든 값은 **Python 무제한 정수**. full product/누산을 정확히 계산한 뒤
  **명시적 하드웨어 경계에서만** 폭을 적용한다.
- NumPy 고정 폭 정수를 연산에 쓰지 않는다(암묵적 wrap 금지).
- 실수 상수는 `fractions.Fraction`으로 **정확한 2진 값**에서 반올림한다.
  따라서 half-LSB tie는 실제 tie이지 float 반올림 부산물이 아니다.
- 반올림 모드와 overflow 정책은 **독립 인자**이고, 모든 resize가 발생 여부를 보고한다.
- float 배열을 만들고 마지막에 한 번 round하는 경로는 없다.

제공 함수: `round_half_even`, `round_half_away`, `truncate_floor`,
`shift_right_round`, `wrap_to_signed`, `saturate_to_signed`, `resize_signed`,
`resize_unsigned`, `quantize_real`(+`extra_scale_log2`), `OverflowCounter`.

검증: `verification/fixed/test_qnum.py` **91개 검사 통과**.
기대값은 정의에서 손으로 적었다. 포함 항목 —
양/음 half-LSB tie(`±2.5 → ±2`, `±3.5 → ±4`), tie에서 두 모드가 반드시 갈리는지,
floor와 nearest의 차이, signed 16/18 경계(`32767`, `-32768`, `±2^17`), wrap과 saturate가
같은 입력에서 다른 값을 주는지, `0.95 → 31130`(문서의 예시값), **양자화 전 배율과
양자화 후 shift가 다름**(`0.01`을 `2^5` 사전 배율하면 10486, 먼저 양자화 후 `<<5`는
10496 → 10 LSB 차이).

## 5. 미확정 항목 (추정으로 채우지 말 것)

1. pre-emphasis·window의 중간 폭·소수부·반올림 위치와 계수 형식.
2. log의 정수 정규화·LUT/근사 구조, 구간, 오차, 출력 형식.
3. DCT 계수 W/F, 누산 폭, 출력 F와 PC 환산 메타데이터.
4. `Fw` 최종값. 16은 후보이며 전체 경로 개선 후 재평가 대상.
5. BFP 목표 peak `T`와 `s` 허용 범위의 최종값.
6. **고정소수점 합격 기준(허용치) 전체.** 2장 수치는 측정값이며 합격 판정이 아니다.
7. FFT 입력·내부·출력 정밀도의 최종 채택값. 보존 원본은 유지하고 확장 모델로 비교한다.
8. 정수 경로의 자원·속도. 비트 수 감소만으로 LUT/DSP/전력 감소를 확정하지 않는다.
