# 고정소수점 선행 실험 결과 (Q1)

작성: 2026-10-04 Asia/Seoul. 작성 범위: 고정소수점 수치 설계·RTL 검증.
정정: 2026-10-04, 사용자 지시에 따라 수치 실험을 인계하여 집계와 해석을 교정했다.
수치 계약은 [FIXED_POINT_QUANTIZATION_PLAN.md](FIXED_POINT_QUANTIZATION_PLAN.md).
후속 FFT 정밀도 비교와 현재 후보 제안은 [FIXED_POINT_PRECISION_REVIEW.md](FIXED_POINT_PRECISION_REVIEW.md).

후속 실험은 24입력·616프레임·6정밀도·2목표를 완료했다. 내부·출력20/F19, 입력16/F15,
목표0.975를 우선 후보로 제안하며 개발 MFCC RMSE 0.00625816, 합성 통합 RMSE 0.894057을
관측했다. 아래 표는 보존된 **기존16비트 pilot** 결과이며, 새 후보의 합격 판정을 뜻하지 않는다.

## 0. 이 실험의 성격 — 혼합 정밀도

**이것은 완성된 고정소수점 MFCC가 아니다.** 실제로 정수로 계산한 구간은 다음 셋뿐이다.

```
float64 pre-emphasis / framing / window     <- 기준과 동일 (정수화 안 함)
  -> FFT 입력 양자화 signed16 / F15          <- 정수
  -> 재사용 FFT 비트모델                      <- 정수, wrap, ties-to-even
  -> 정수 Power / Mel 누산                    <- 정수, 반올림 없음
  -> float64 로그 floor / 정규직교 DCT        <- 정수화 안 함 (Q2)
```

실행 manifest의 `experiment_class`는 모든 run에서 `mixed_precision`이다.
**전체 fixed 모델 완성으로 보고하지 않는다.**

또한 이 문서의 어떤 수치도 **RTL 결과나 보드 결과가 아니다.** RTL은 작성하지 않았고
합성·시뮬레이션·보드 실행도 하지 않았다. 평가용 음성 20개는 열지 않았다.

### 1.1 front-end 자기 검사

후보 경로는 동결 기준의 `windowed.bin`을 그대로 입력으로 쓴다. 추가 합성 입력만은

| 단계 | fft | power | mel_energies | log_mel | mfcc |
|---|---|---|---|---|---|
| max abs diff | 3.97e-15 | 2.22e-16 | 3.33e-16 | 1.07e-13 | 5.33e-14 |

재생성한 Mel 필터뱅크와 bin edge는 동결 표와 **bit 단위로 동일**하다.

manifest의 `frontend_selfcheck_pcm_to_window_max_abs`에서 `frames` 값은 프레임 수가 아니라

## 2. 후보

| 후보 | 양자화 위치 | 지수 선택 | 비고 |
|---|---|---|---|
| **A** 기준 | 없음 | — | 동결 float64 배열. 읽기만 함 |
| **B** `fixed_alpha_half` | `quantize(u * 2^-1)` | `s = 0` 고정 | `MFCC_SPEC.md:123`의 `z = u/2` |
| **C** `bfp_pre_quant` | `quantize(u * 2^(s-1))` | **양자화 전에** float64 프레임 peak에서 `s` 선택, 목표 peak 0.5 FS | 이번 BFP 후보 |
| **D** `q15_then_shift` | `quantize(u * 2^0)` 후 정수 `<< (s-1)` | C와 같은 `s` | **보조 비교.** 먼저 양자화하므로 잃은 정보를 되살리지 못한다 |
| **C′** `bfp_pre_quant_t975` | C와 동일 | 목표 peak **0.975 FS** | 2차 관찰. 주 후보 아님 |

B·C·D 모두 양자화 결과를 `[-32767, +32767]`로 clamp한다.
D만 양자화 시점이 다르므로 **큰 진폭에서 saturate가 발생한다**(아래 3.3).

C/C′의 실제 지수 선택은 `peak * 2^(s-1) * 2^15 <= T`인 최대 s를 고르는
**반올림 전 peak 기준**이다. T=16384 또는 31949이며, 반올림 후 peak와 비교한다는
기존 양자화 계약 문구를 정정했다. 자세한 경계 예와 clipping 정의는 수치 계약 1.2절을 따른다.

**전체 24개 입력 합계:** FFT overflow 프레임 B/C/D 모두 **0**, 지수 clamp **0**,
입력 clipping은 B·C가 **0**, **D만 923 frame-samples / 1,385 events**다.
단계별로 `quantize_width_policy` 923회, `symmetric_clamp` 462회다. 한 샘플이 두 단계를
거치면 이벤트는 2회지만 clipped frame-sample은 1개로 센다. 프레임은 겹치므로 이는
서로 다른 원본 PCM 위치 수가 아니다. 입력별로 `fullscale_alternating` 798개/1,197회,
`noise_pcg64_seed20261004` 125개/188회이며 나머지는 0이다.
기존 "1,385 샘플"은 **이벤트 수를 샘플 수로 잘못 부른 표현**이었다.
D는 `α = 1` 시점에 먼저 양자화하므로
pre-emphasis 후 `|u| > 1`인 구간이 잘린다. 이것이 "양자화 후 shift"와
"양자화 전 배율 선택"의 구조적 차이다.

### 3.4 BFP 목표 peak 2차 관찰 (주 후보 아님)

같은 pre-quantization 지수 선택에서 목표 peak만 0.5 FS → 0.975 FS로 바꾼 결과
(개발 음성 534프레임):

| 지표 | 목표 0.5 FS | 목표 0.975 FS |
|---|---|---|
| MFCC max / RMSE | 1.664e+01 / 1.218e+00 | **3.379e+00 / 5.586e-01** |
| log-Mel RMSE | 9.402e-01 | **4.472e-01** |
| Mel floor 발동 | 102 | **24** |
| 지수 `s` 범위 | 0…10 | 1…11 |
| FFT overflow 프레임 | 0 | **0** (24개 입력 전체) |
| 입력 saturate | 0 | **0** (24개 입력 전체) |

2의 거듭제곱 지수는 목표 peak를 0.5로 잡으면 범위를 약 25~50 % 활용하며,
이번 개발 프레임에서는 약 28 %만 쓰는 사례가 있다
(예: 프레임 peak 0.5647 → `s=0` → 양자화 peak 0.282 FS). 목표를 0.975로 올리면 그 손실이
줄어든다. **다만 FFT 재사용 검토에서 peak 0.975의 무overflow는 시험한 두 적대 신호군에
한정된 관측이며 일반 보장이 아니다.** 채택하려면 `out_overflow` 감시가 필수다.

| B 고정 | 473 | 6.576e+01 / 7.293e+00 | 61 | 1.300e+00 / 1.549e-01 |
| C BFP | 81 | 1.664e+01 / 3.118e+00 | 453 | 9.784e-01 / 9.567e-02 |
| D Q15후 shift | 81 | 1.664e+01 / 3.128e+00 | 453 | 9.784e-01 / 9.320e-02 |

### 4.2 프레임 레벨별 (개발 음성)

| 후보 | peak < 1e-3 (10프레임) | 1e-3…1e-2 (75) | 1e-2…1e-1 (226) | 1e-1…1 (223) |
|---|---|---|---|---|
| B 고정 max / 0인 band | 6.340e+01 / 258 | 6.576e+01 / 952 | 3.291e+01 / 782 | 2.561e+01 / 315 |
| C BFP max / 0인 band | **1.439e-02 / 0** | **2.594e-01 / 0** | 5.600e+00 / 17 | 1.664e+01 / **85** |

이 개발 입력에서는 **BFP가 조용한 프레임의 오차를 크게 줄이고, 큰 잔차는 상대적으로
큰 프레임에 모인다.** 큰 프레임에서는 지수를 더 올릴 여유가 줄어든다(3.4 참조).
이 층화 결과만으로 입력·내부 FFT·최종 출력 양자화의 개별 원인을 분리할 수는 없다.

### 4.3 남은 오차의 위치 (C 후보)

- 정수 Mel이 0이 되는 band index: **0, 1, 2, 3, 4** (각각 78, 11, 8, 4, 1회). 그 위 band는 0회.
- 그 (band, frame) 셀의 기준 에너지: **3.779e-09 … 7.425e-07**,
  기준 `ln` 값 **−19.394 … −14.113**. floor가 대입하는 값은 `ln(1e-12) = −27.631`이므로
  셀당 8~13 nats의 오차가 생기고 DCT로 전 계수에 퍼진다.
- 이 위치 분석은 **에너지가 사라진 셀**을 보여 주지만, "최종 16비트 FFT 출력 폭만이 원인"
  이라는 기존 단정은 철회한다. 입력 양자화, FFT 내부 반올림·twiddle, 최종 출력 격자를
  따로 비교해야 한다. 후속 정밀도 실험은 보존 원본 `fft_bitmodel.py`를 유지하고
  `fft_bitmodel_wide.py`에서 수행한다.
- 여기서 로그는 float64다. 작은 양의 기준 에너지가 0 또는 floor 아래로 떨어지면
  `ln(max(E, 1e-12))`의 비선형 변환이 차이를 크게 만든다. 정수 로그 구현의 문제로
  해석하지 않으며, 향후 정수 log도 사라진 에너지를 복구하지 못한다.
- ablation 경로의 RMSE 차이를 각 단계의 독립적인 오차 기여도처럼 더하거나 빼지 않는다.

## 7. 후보 제안

### 7.1 측정에 근거한 제안

**고정 배율보다 BFP(양자화 전 지수 선택)를 권한다.** 근거:

1. 개발 음성 전체 프레임에서 MFCC max **65.8 → 16.6**, RMSE **6.86 → 1.22**.
2. Mel floor 발동 **2307회(473프레임) → 102회(81프레임)**.
3. 입력 양자화 손실 RMSE **1.76e-5 → 4.17e-6**.
4. 이 24개 시험 입력에서 B·C의 overflow와 clipping은 모두 0이다. 모든 입력에 대한 보장은 아니다.
5. 합성·추가 입력에서도 거의 전부 개선되고, 악화된 경우는 `noise_pcg64`
   (2.759e-02 → 2.843e-02, 이미 full scale에 가까워 BFP가 할 일이 없는 입력) 하나뿐이다.

**"양자화 후 shift"(D)를 BFP라고 부르면 안 된다.** 개발 음성에서는 C와 거의 같아 보이지만
`small_alternating_1`에서 1.756e-04 vs 1.477e+01, `pcm_one_lsb_sparse`에서
2.205e-02 vs 4.637e+00, `noise_pcg64`에서 2.843e-02 vs 3.171e+00으로 갈린다. 또 D만
입력 clipping 923 frame-samples와 1,385 단계 이벤트를 만든다.

### 7.2 아직 제안하지 않는 것

- **합격 기준(허용치).** 위 수치는 측정값이다. fixed 허용치는 아직 없다.
  개발 음성에서 MFCC RMSE가 1.22(C) 또는 0.56(C′)인데, 이것이 충분한지는
  하류 사용처(AI 입력)의 요구로 판단해야 하며 이번 범위 밖이다.
  **평가 결과를 보고 floor·입력·정답을 바꾸지 않는다.**
- **BFP 목표 peak의 확정값.** 0.975가 0.5보다 좋지만(3.4) overflow 무발생은
  관측 범위 한정이다.
- **`Fw`의 확정값.** Fw=16의 계수 기여는 2.3e-5 nats로 현재 지배적이지 않으나
  전체 경로가 개선되면 재평가해야 한다.

## 8. 다음 단계 (Q2)

### 8.1 정밀도 비교 후 남는 전체 정수화 단계

이번 인계 작업은 오류 수정·FFT 정밀도 비교·후보 제안까지이며, 아래 구현이나 새 RTL은 시작하지 않는다.

1. **pre-emphasis와 window.** BFP를 실제로 쓰려면 지수를 **정수 전처리 출력**에서 골라야
   한다. 지금은 float64 프레임에서 고르고 있어 하드웨어와 다르다. 이 단계가 정해져야
   BFP 후보가 구현 가능한 제안이 된다.
2. **log.** 전체 정수화를 위해 정규화·LUT 구조와 floor 비교를 설계하고 추가 오차를 측정한다.
   현재 log-Mel max 13.5는 float64 로그가 앞단 에너지 손실을 확대해 보인 결과이며,
   정수 log 구현을 도입하면 그 손실이 해결된다는 뜻이 아니다.
3. **DCT.** 계수·누산 폭과 출력 F를 정하고 PC 환산 메타데이터를 고정한다.

### 8.2 아직 비트정확하지 않은 단계

pre-emphasis, framing, window, log, DCT. 이 다섯 단계는 현재 float64이며
**RTL 비트 비교의 기준이 될 수 없다.**

### 8.3 다음 RTL 모듈 제안

새 RTL은 이번 작업 범위 밖이다. 아래 Power/Mel 모듈은 **signed16/F15 FFT 출력 및
Fw=16 후보에 한정한 후속 구상**이다. 이 조건의 정확한 곱·누산 상한을 확인했지만,
Mel 계수 폭이나 전체 경로의 최종 폭을 확정한 것은 아니다. FFT 출력이 넓어지면 다시 산정한다.

제안 모듈(작성 시 `RTL_CODING_RULES.md`의 금지·명명·2-process·리셋 규약 적용):

| 모듈 | 입력 | 출력 | 비고 |
|---|---|---|---|
| `mfcc_power_u32` | FFT 자연 순서 `out_re/out_im` signed16, `bin index`, `valid/last` | `psum` unsigned 32 | 제곱·합만. 반올림 없음 |
| `mfcc_mel_accum` | `psum` unsigned 32, Mel 가중치 ROM unsigned 17 | `T_m` unsigned 52(Fw=16), band index, `valid/last` | 누산 폭은 계수표에서 유도. ROM 초기화 방식은 `RTL_CODING_RULES.md` 3장에 따라 먼저 문서화 |

두 모듈 모두 `valid && ready`에서만 수락하고, 출력 stall 중 data/index/last/valid를
유지해야 한다(`RTL_CODING_RULES.md` 4장). 재사용 FFT에는 출력 stall 포트가 없으므로
그 경계의 buffer/credit 설계가 선행 조건이다.
