# Integer PCM frontend

`mfcc_fixed_frontend.sv` implements the version 2 candidate. It accepts PCM only on `i_pcm_valid && o_pcm_ready`. Input gaps preserve the previous accepted PCM sample. `i_clip_start` aborts pending work and resets the clip's previous sample, frame number and ring pointers. Simultaneous `i_clip_start && i_pcm_last && !i_pcm_valid` represents an empty clip and emits a completion pulse. For nonempty clips, `i_pcm_last` accompanies the last accepted sample. Incomplete trailing frames are discarded.

The continuous preemphasis uses exact alpha 19/20. The arithmetic numerator is `(20*pcm - 19*previous)*32768`; its division by 20 is rounded to nearest, ties to even, producing signed32/F30. The RTL computes the exact equivalent `(pcm-previous)*32768 + RNE(previous*8192/5)`. An unsigned16 reciprocal product `m*52429 >>18` gives exact floor(m/5), and a five-entry remainder table finishes the correction. The input is captured, its quotient and signed correction are separately registered, then the result is written; PCM ready is low during those three processing cycles. This removes the synthesized 38-bit divider and separates the reciprocal/correction logic from the final BRAM input addition. Symmetric Hamming is unsigned31/F30. A registered signed64 product is rounded once by 30 bits into signed32/F30. The rounded value and its unsigned32 magnitude have separate registers before the peak comparison; no additional rounding is applied.

Each complete 512-sample frame scans the windowed peak before choosing the greatest s in [-2,24] for which `peak_q30 * 2^(s-16) <= 31949`. Silence uses s=0. FFT input is RNE(windowed_q30 / 2^(16-s)), saturated to [-32767,32767]. Legal shifts need at most 18 right bits or eight left bits, so quantization uses an exact signed40 quotient and unsigned18 remainder mask. Quotient and rounding decision are registered before addition and clipping; this preserves every integer result while cutting the former 64-bit mask/subtract/round critical path. Its interpretation is signed16/F15 with extra scale 2^(s-1). The frame index starts at zero; `o_index` runs 0…511; `o_last` marks index 511. `o_error` identifies a detected resize/clipping error. All output fields remain stable during output stalls.

The design uses two block RAM buffers, each 512×32: one ring stores continuous preemphasis, and one frame buffer stores window products. The ring explicitly instantiates vendor `xpm_memory_spram` because an initial inference attempt mapped it to distributed RAM despite `ram_style="block"`; the window buffer remains inferred. The XPM read latency is one clock, writes and reads occupy disjoint FSM states, and no authored initialization/loop exception is used. There is one registered RAM read and at most one read transaction in flight. RAM contents are neither reset nor duplicated into a next-state array. A frame is processed and emitted while PCM ready is low, then the next 160 accepted PCM samples advance the overlapping frame. This is a deliberately sequential, bounded-storage implementation; an unconstrained nonstallable PCM source needs an external rate buffer.

Generate the coefficient case module with `scripts/generate_fixed_integer_rtl.py`; float arithmetic is confined to that offline generator. Runtime frontend arithmetic contains no float operations. Numeric vectors are produced by `scripts/run_fixed_full_model.py`. Vivado unit simulation/synthesis is launched by `scripts/verify_fixed_integer_rtl.py`; report files distinguish simulation, synthesis and timing. Presence of RTL source alone does not indicate verified implementation or accepted MFCC accuracy.

The window coefficient is registered in the same `S_WINDOW_READ` cycle as the preemphasis BRAM read. The following product cycle consumes the aligned data and coefficient for the same index. This separates coefficient decode from multiplication without adding a cycle or changing frame/index order.
